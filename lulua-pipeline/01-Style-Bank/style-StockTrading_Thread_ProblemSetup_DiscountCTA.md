# Part 3: Master Universal Wireframe Blueprint (Elastic Narrative Phases)

## Phase 0 — Input Depth Analysis & Dynamic Length Setting

Before drafting, analyze the source material and identify:

- Number of distinct tool/system features or data panels.
- Whether a clear before/after verification loop exists.
- Whether an incentive/fee structure exists and how many tiers/eligibility conditions it contains.
- Whether execution mechanics require a separate walkthrough.
- Audience familiarity with the domain.

Set N dynamically from 3 to 15 based on the number of atomic content modules. Never inherit a fixed count from the source. Label posts as 1/N, 2/N ... N/N.

## Phase 1 — Relatable Failure Confession, Tool Introduction, Incentive Teaser

Open with a self-diagnosed mistake: “My bad results were not wrong analysis—they were late analysis.” Introduce the enabling tool/system as the solution and state that it is free or available. Tease a time-sensitive offer and defer the details to drive scrolling.

**Scaling:** If the incentive is weak or absent, compress this into one short hook. If the incentive is complex, reference it only and reserve the full breakdown for a later phase.

## Phase 2 — Core Observability Mechanism

Deliver an atomic explainer for the first feature cluster. Include:

- A sorting/filtering control.
- A cost-basis or average metric.
- A visual overlay or plot.
- A concrete pattern the user should look for (e.g., flat baseline with one slowly rising signal).
- A non-advice disclaimer bridge.

**Scaling:** One atomic feature per post. If the first feature has multiple sub-panels, split into 2/N and 3/N. Otherwise keep as a single 2/N post.

## Phase 3 — Post-Session Verification

Provide a second atomic explainer: after the live event or session, break large events into granular counterparties or records. Show that identical headline numbers can hide entirely different real-world dynamics. Close with a line that creates retrospective awareness.

**Scaling:** If verification uses multiple panels, allocate one post per panel. If it is simple, consider merging with Phase 2.

## Phase 4 — Live/Runtime Interpretation

Provide a third atomic explainer for reading live status queues. Define status labels such as open, matched, and amended/withdrawn. Show how to separate real friction from fake friction by observing status behavior. End with a confidence-building bridge.

**Scaling:** If live statuses are simple, combine with Phase 3. If complex, create a dedicated post.

## Phase 5 — Workflow Integration

Explain how to combine all previous panels/widgets on one screen. Describe drag, resize, group, and saved presets. Split presets by use case, such as monitoring versus execution. End with a transition into execution.

**Scaling:** If customization is minimal, compress into one paragraph. If multiple presets or layouts exist, create a dedicated post.

## Phase 6 — Execution Engine & Risk Control

Contrast analysis with execution. Include the exact claimed speed or latency. Walk through interaction steps: input value → click level → drag amend → side cancel → bulk cancel. Mention the ability to skip confirmation and immediately attach a risk warning. Instruct smaller size or volume while learning.

**Scaling:** If the walkthrough exceeds four steps, split speed claim and interaction steps into two posts. If no execution mechanics exist, omit this phase.

## Phase 7 — Incentive Detail & Eligibility

Break down the pricing baseline, discount tiers, worked cashback examples, and payout timing. Define eligibility for new versus existing users, minimum deposit/volume thresholds, and what is not eligible. Clarify what remains free. End with a terms link.

**Scaling:** If no incentive exists, skip. If tiers exceed three or eligibility rules are long, split into multiple posts—one for tiers, one for eligibility.

## Phase 8 — Conversion CTA, Referral, Community, Disclaimer

State platform availability. Provide a crafted one-liner for serious users. Give a direct download link and a web fallback. Include a referral code. Invite questions via replies to generate comments. Close with a full risk/education disclaimer.

**Scaling:** If community or referral is not needed, collapse CTA into a single post. If a legal disclaimer is required, keep it as the final post.

## Dynamic Content Scaling Directives

- Never inherit the source post count. Analyze the source material and count distinct atomic modules first.
- Each phase can be one post, two posts, or combined with an adjacent phase based on real data depth.
- Explicitly mark every post as 1/N, 2/N ... N/N to preserve sequence and completion expectations.
- If the source lacks a phase, do not invent it. If it contains an extra phase, insert it logically into the phase flow.
